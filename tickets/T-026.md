Contracts:
- **Model identity plumbing (plan-review I-8 — one source of truth):** every function that needs model ids takes them as EXPLICIT parameters (`generator_model: str`, `judge_model: str`) — this module performs NO generator-side env lookup. The generator id's single source is T-023's `resolved_generator_model()`; this module's CLI `main()` obtains it via a documented LAZY import inside the function body (same mechanism as T-025's `_resolve_answer_fn`, same justification: T-023 is same-wave and unmerged during implementation; the CLI runs only post-merge, post-provisioning), through a monkeypatchable seam `_resolve_generator_model()`. The judge's own id: `ONRECORD_JUDGE_MODEL` env read by `default_judge()` only, defaulting to a module constant `DEFAULT_JUDGE_MODEL` [research-required at provisioning].
- `assert_cross_family(generator_model: str, judge_model: str) -> None` — family inferred by prefix map (`claude*`→anthropic, `gpt*`/`o*`→openai, `gemini*`→google, `voyage*`→voyage, else "unknown"); same family OR either unknown → raise `CrossFamilyViolation` (fail closed — an unverifiable pairing never silently counts, proposed).
- `build_judge_prompt(question, claim, chunks) -> str` — one claim per call (claim-level, matching spec §5), chunk texts as evidence, STRICT output protocol: a single JSON object `{"verdict": "supported"|"unsupported"|"contradicted", "evidence_chunk": int|null}`.
- `parse_verdict(raw: str) -> dict` — tolerant extraction (first JSON object in the text); unparseable/invalid enum → `{"verdict": "unparseable", "evidence_chunk": null}` — never raises (judge flakiness is data, not a crash; mirrors the LESSONS failures-as-data rule).
- `judge_answer(question, answer_text, chunks, judge_fn) -> dict` — claims via `split_claims`; per-claim verdicts; **a `judge_fn` call that RAISES (transport error, provider 5xx after retries) is also failures-as-data (plan-review M-8): caught per-claim, recorded as `{"verdict": "error", "evidence_chunk": null}`, run continues — prior verdicts are never lost.** Returns `{"claims": [{"claim", "verdict", "evidence_chunk"}], "supported": int, "total": int, "faithfulness": supported/total (0.0 when total==0)}`; `unparseable` and `error` both count NOT supported.
- **Validation gate (locked, spec §5):** `evalsets/faithfulness_labels.jsonl` rows `{"label_id": str, "question": str, "answer_text": str, "chunk_texts": [str], "claim": str, "human_verdict": "supported"|"unsupported"|"contradicted"}` — this ticket ships the SCHEMA + loader + a committed 2-row EXAMPLE-ONLY pair (marked `"label_id": "example-*"`, excluded by the loader's default filter); the ~10 real hand labels are an OWNER action (open question #4). `validate_judge(judge_fn, labels, judge_model, generator_model, min_agreement=0.8) -> {"agreement": float, "passed": bool, "n": int, "disagreements": [...]}` — calls `assert_cross_family` first — and on pass writes `artifacts/judge_validation.json` `{timestamp, judge_model, generator_model, agreement, passed, n}`.
- **The verdicts-don't-count mechanism:** `run_faithfulness(answers, judge_fn, judge_model, generator_model, validation_path="artifacts/judge_validation.json") -> dict` REFUSES (raises `JudgeNotValidated`) unless a validation artifact with `passed: true` and matching `judge_model` exists; on success appends `{"timestamp", "git_sha", "corpus_version" (T-018 `read_manifest`), "kind": "faithfulness", "metrics": {mean_faithfulness, per_answer}}` to `artifacts/rag_eval.jsonl`. That row shape is pinned IDENTICALLY in T-025 (verified matching by the plan review) — a shared schema stated in both tickets, not a code import; T-025 is same-wave and neither imports the other.
- `default_judge()` — OpenAI chat-completions adapter (httpx), `OPENAI_API_KEY`; absent → `JudgeNotConfigured` naming the var. **Secret hygiene (locked, LESSONS T-014):** library loggers silenced/redacted around keyed calls; root-logger sentinel test required.
