Wiring map:
1. **Ask request**: `askSend()` posts `{question, mode, k}` (mode from the view's mode control if present, else "hybrid"; k=8 stays) and RETAINS the parsed response in state.
2. **Answer rendering (the pinned shape, verbatim keys)**: `text` rendered with `[n]` markers turned into interactive citation chips — click/hover surfaces the matching `citations[]` entry (snippet + working `deep_link`, opening the receipt; every citation is a deep link, spec §5). `retrieved[]` listed below the answer in the design's existing result-row language, `cited: true` rows visually distinguished. `grounding` shown as a badge: status (grounded/partial/ungrounded) + `supported_claims/total_claims` count, in the design's voice.
3. **Refusal state**: `refusal != null` → the design's honest-decline treatment: `refusal.reason` + `suggestions[]` as tappable chips that re-ask (no fake answer text beyond the pipeline's decline sentence).
4. **Error states**: 503 flat `{"error": ...}` (embeddings/generator not provisioned, index missing) → an honest "not provisioned yet" card naming what's missing, in the design language — distinct from the api-down state; 422 → inline validation. The QUEUED-FOR-THURSDAY teaser card and the "PREVIEW THREAD · illustrative answers" banner + hardcoded example threads are REMOVED (demo data may survive only in the existing api-down state, labeled, per T-016 §7 convention).
5. **Search view mode param**: the search fetch sends `mode=` from the mode toggle (lexical default); semantic/hybrid results render through the existing result pipeline (the 9-key shape is unchanged); a 503 on those modes shows the same "not provisioned" treatment instead of the stale `available_wednesday` teaser copy.
6. **WIRING.md**: update the Ask section (§ around lines 27-32, 300, 349-351) + the verification checklist to the landed states; note the teaser-copy removal.
