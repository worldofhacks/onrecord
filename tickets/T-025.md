## Context
Datasets + deterministic measurement tooling. The runner consumes answers as PLAIN DICTS of the pinned /api/answer contract (tests/unit/test_api.py PINNED-FOR-THURSDAY — locked), via an injected `answer_fn(question) -> dict`; it does NOT import T-023 (no dependency, wave-parallel safe) — refusal detection is simply `row["refusal"] is not None` per the contract.

Datasets (JSONL, one object per line):
- `evalsets/qa.jsonl` rows: `{"qa_id": str, "question": str, "criterion": str, "answer_doc_ids": [str, ...], "origin": "judgments" | "owner"}`. `answer_doc_ids` are corpus doc ids VERBATIM (`yt:VIDEO:segNNN` shape is load-bearing — locked). **Seeding via "answer-grade derivation" (proposed, flagged as owner open-question #6):** ship `derive_qa_from_judgments(judgments_path, answer_grade: int = 2) -> list[dict]` — turns each judged query with ≥1 doc at grade ≥ `answer_grade` into a QA row (question = the query text VERBATIM, always — no "trivially rephrasable" judgment calls inside a deterministic transformer, plan-review M-3; owner rewrites land as origin="owner" rows; answer_doc_ids = the qualifying doc ids; origin="judgments") — deterministic, honest, zero fabrication. **Naming note (plan-review I-6):** "answer-grade derivation" (grade == 2 by default, injected) is deliberately a DIFFERENT concept from T-020's "coverage relevance" (grade ≥ 1, injected) — different measurements, distinctly named, both parameterized so OQ-6 resolves by config, never a re-freeze. The committed qa.jsonl = transformer output over the CURRENT judgments (≥5 rows now; regenerated by the orchestrator after the owner's 15-query Thursday labeling session).
- `evalsets/unanswerable.jsonl` rows: `{"qa_id": str, "question": str, "reason": "out-of-corpus" | "out-of-scope" | "false-premise", "notes": str}`. Ship ≥10 authored rows (agent-authored is legitimate here — unanswerable-by-construction, e.g. the spec's own "what does Loudoun County think about Solana?"; each row's notes must say WHY the corpus cannot answer it). These are data, not code — owner review invited, not required for merge (proposed).

`onrecord/rag/qa_eval.py`:
- `load_qa(path) / load_unanswerable(path)` — schema-validating loaders; malformed row → error naming line number and missing/invalid field (never a silent skip: eval sets are graded artifacts).
- `evaluate_refusal(answer_fn, answerable_rows, unanswerable_rows) -> dict` — `{"refusal_rate": <refused/total on unanswerable>, "false_refusal_rate": <refused/total on answerable>, "per_item": [{"qa_id", "kind", "refused": bool}], "n_answerable": int, "n_unanswerable": int}`.
- `answer_recall(qa_rows, retrieve_fn, k=10) -> dict` — per row, `retrieve_fn(question) -> list[doc_or_chunk_id]`; a labeled answer doc counts retrieved if its doc_id appears OR a returned chunk-style id's constituent doc_ids include it (accept an optional `chunk_doc_ids: Callable[[str], list[str]]` resolver, default identity — keeps this ticket independent of T-020 while staying chunk-aware). Returns mean recall@k + per-query values.
- CLI main: appends rows to `artifacts/rag_eval.jsonl`: `{"timestamp", "git_sha", "corpus_version" (via T-018 `read_manifest`), "kind": "refusal" | "answer_recall", "metrics": {...}}` — mode-agnostic sidecar artifact; eval/run.py's frozen history is untouched (locked constraint). **Real-pipeline wiring mechanism (plan-review I-9):** `main()` obtains its real `answer_fn` through a module-level seam `_resolve_answer_fn() -> Callable`, which LAZILY imports `onrecord.rag.answer` + retrieval INSIDE the function body — documented as safe because the CLI only runs post-wave-9-merge and post-provisioning (T-023 is same-wave and unmerged during this ticket's implementation; a module-level import would be a collection error in the wave-9 worktree). AC-5 exercises `main()` with the seam monkeypatched; the lazy import path itself is orchestrator-eval territory.

## Acceptance Criteria
- **AC-1**: Loaders — valid fixtures load; a row missing `answer_doc_ids` (or with empty question, or bad `reason` enum) errors naming the line number and field.
- **AC-2**: `evaluate_refusal` math — fake answer_fn refusing 3 of 4 unanswerable and 1 of 5 answerable → refusal_rate 0.75, false_refusal_rate 0.2, per_item entries exact.
- **AC-3**: `answer_recall` hand-computed on a fixture (including the chunk-resolver path where a merged chunk id covers a labeled doc).
- **AC-4**: `derive_qa_from_judgments` — from a judgments fixture with grade-2/1/0 rows: at the default `answer_grade=2` only grade-2 docs become answer_doc_ids and queries with none are skipped; at `answer_grade=1` the grade-1 docs qualify too (both thresholds pinned — plan-review I-6/OQ-6); questions are the query text verbatim; output is deterministic (stable ordering) and doc ids are byte-identical to the input.
- **AC-5**: CLI artifact row shape exact via a monkeypatched `_resolve_answer_fn` seam (plan-review I-9), `corpus_version` read from a tmp manifest ("unversioned" fallback covered).
- **AC-6**: The committed evalsets validate against their own loaders (a test loads the real files); unanswerable.jsonl has ≥10 rows spanning ≥2 distinct reasons.
