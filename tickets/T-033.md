## Context — the reference (https://paste.trade, surveyed 2026-08-13)

paste.trade's unit is a **call**: an account mentions a ticker at a timestamp;
the entry price is snapshotted at that moment; a leaderboard ranks calls by
performance since the mention. The load-bearing mechanics, observed live:

1. **Entry anchored to the mention timestamp** — performance is measured FROM
   the moment of the utterance, not from an arbitrary chart origin.
2. **Peak-since marker** ("▲165.6% ATH") — max favorable excursion since the
   call, shown beside current performance. Separates "was right at some point"
   from "is right now".
3. **Attribution + receipt** — every row names the caller and deep-links the
   original post ("Open SNDK trade source"). The claim is auditable.
4. **Co-mention merging** ("+6" chips) — duplicate calls on the same ticker
   collapse into one row with a count.
5. **Time windows** (Today / Yesterday / Last 7 days) and a leaderboard sort
   by return.

## The OnRecord mapping

Our record already has everything paste.trade builds on — but our "callers"
are **the civic/financial paper trail itself**: a county meeting that discusses
a company, a filing that names a counterparty. The feature: *when the record
mentions a ticker, snapshot the price at that mention's timestamp and track
what happened next* — with our existing receipts as the trade source.

| paste.trade | OnRecord |
|---|---|
| Caller (@handle) | Source: jurisdiction + meeting (SWORN) or filer (FILED) |
| Call timestamp (intraday) | Document date (daily grain — see Honest-grain note) |
| Entry price at call time | Close on mention date (prior close if non-trading day) |
| % since call | % from mention-date close to latest close |
| ▲ ATH since call | Max close between mention date and today, as % of entry |
| "Open trade source" | Existing receipt deep link (YouTube `?t=` / EDGAR URL) |
| +N co-mentions | Same ticker mentioned in N other docs inside the window |
| LONG/SHORT direction | **Out of scope v1** — direction/sentiment inference is Promise-Ledger territory (follow-on ticket) |

**Honest-grain note (pinned for the UI copy):** paste.trade anchors intraday
because tweets are intraday. Our record is day-grained (meeting dates, filing
dates), so entries anchor to the mention date's close via the existing stooq
daily pipeline. The UI must label the grain ("from close of YYYY-MM-DD"),
never fake intraday precision. Keyless deploys keep working: stooq is
keyless, and the price cache + 503 ladder conventions from T-015/T-024 apply.

## Build sketch (planner refines into tickets)

- **Mention extraction** (`onrecord/analysis/mentions.py`): registry-driven
  (ticker + company aliases from `onrecord/registry.py`) scan over the index —
  emit `(ticker, doc_id, doc_date, deep_link, snippet)` rows; alias matching
  must be word-boundary-safe (ticker "BE" must not fire on the verb; require
  cashtag/company-name or uppercase-exact context — Test Agent encodes the
  false-positive corpus).
- **Performance join**: reuse `onrecord.ingest.prices` daily closes (cached);
  compute entry close, current return, peak-since return per mention row.
- **API**: `GET /api/mentions?window=7d|30d|90d|all&sort=return|date&k=50` →
  `{rows: [{ticker, source_type, jurisdiction_or_filer, doc_id, date,
  deep_link, snippet, entry_close, latest_close, return_pct, peak_pct,
  co_mentions}], as_of, grain: "daily-close"}`. Plain `def` handler
  (T-024/T-032 convention), precomputed/cached — no per-request index scans
  (T-032's `/api/tickers` lesson).
- **UI**: Tickers view gains a "Record calls" leaderboard — window toggle,
  return-ranked rows, SWORN/FILED badges, receipt deep links, grain label.
  Both UI copies byte-identical (`cmp` gate).
- **Eval hook**: mention extraction is deterministic → frozen tests; no LLM
  in the loop for v1.

## Acceptance criteria (sketch — Test Agent refines)

- AC-1: mention rows are reproducible from (index, registry, prices cache)
  alone — a rebuilt corpus yields identical rows for identical inputs.
- AC-2: entry price = close on mention date; non-trading-day mentions anchor
  to the most recent prior close; both cases pinned by tests with a frozen
  price fixture.
- AC-3: peak_pct ≥ return_pct always; both computed from closes only.
- AC-4: ticker alias matching passes the false-positive corpus (short/common
  tickers in ordinary prose do not fire).
- AC-5: `/api/mentions` keyless behavior: serves cached/stooq data with no
  keys configured; degrades per the 503 ladder only when the price pipeline
  itself is unavailable.
- AC-6: UI renders the leaderboard from the pinned response shape; both UI
  files byte-identical.

## Out of scope

Intraday anchoring (paid data), LONG/SHORT or sentiment inference on the
mention (Promise Ledger follow-on), portfolio/simulated-PnL framing (we track
the record's calls, we do not give investment advice — UI copy must not
recommend trades), non-registry tickers.
