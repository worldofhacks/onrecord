## Context
The ranking layer over the merged engine. New module onrecord/rank/bm25.py + a ranked entrypoint onrecord/search/ranked.py (new file — do not edit boolean.py). Contract:
- `bm25_score(tf, df, N, doc_len, avg_doc_len, k1=1.5, b=0.75) -> float` using probabilistic IDF `ln(1 + (N - df + 0.5)/(df + 0.5))` and saturation `tf*(k1+1)/(tf + k1*(1 - b + b*doc_len/avg_doc_len))`.
- `ranked_search(index, query, k=10, k1=1.5, b=0.75, analyzer=None) -> list[SearchResult]` — OR-semantics candidate set, sum of per-term BM25, top-k via heap, ties broken by doc id for determinism. SearchResult.score = BM25 score; snippet = ±80 chars around the doc's first query-term position (positions are in the index) with the term visible.
- CLI wiring is T-013's scope — NOT here.

## Acceptance Criteria
- **AC-1**: Given N=10, df=1 vs df=5 for two terms with identical tf/doc stats, the df=1 term contributes a strictly higher score (IDF ordering).
- **AC-2**: Given the same doc duplicated except one has tf=10 vs tf=1 for a query term, the tf=10 doc scores higher, and marginal gain shrinks: score(tf=2)-score(tf=1) > score(tf=10)-score(tf=9) (saturation).
- **AC-3**: Given two docs with identical tf but lengths L and 3L (b=0.75), the shorter scores higher; with b=0, scores are equal (length normalization knob).
- **AC-4**: Given a term in >half the corpus, IDF stays positive (the probabilistic-variant guarantee).
- **AC-5**: Given a tiny corpus with known stats, ranked_search returns docs in exact hand-computed score order with correct top-k truncation and deterministic tie-break.
- **AC-6**: Given a matched doc, the snippet contains a query term and is ~160 chars centered on its first occurrence position.

## Test Plan
- Unit (deterministic): AC-1..AC-6, hand-computed against the formula; property (hypothesis): IDF strictly decreases as df rises for fixed N; adding a query-term occurrence never lowers a doc's score.
