## Context

Every `/api/prices/{ticker}` response is `{"series": [], "significant_moves": []}`
on prod AND locally. Diagnosis (2026-08-13):

- stooq (primary) no longer serves CSV: it returns a JavaScript SHA-256
  proof-of-work anti-bot challenge page. `parse_stooq_csv` correctly yields
  zero rows; `_try_stooq` correctly returns None.
- FMP (fallback) is inert: `FMP_API_KEY` was never configured anywhere.
- Empty results are correctly NOT cached, so every request re-fails live.
- Downstream is healthy and dark: `significant_moves` + `nearby_receipts`
  (the receipt-joined move timeline) and the UI detail pane (chart + "does
  the record explain this move?" ranking) are fully built and frozen-tested;
  they just never receive a series.

Verified working replacement: Yahoo Finance chart API
(`query1.finance.yahoo.com/v8/finance/chart/{sym}?range=2y&interval=1d`),
keyless with a browser User-Agent; returns JSON timestamps + closes.

## Acceptance criteria

- AC-1: `_try_yahoo` parses a Yahoo chart JSON fixture into the pinned
  ascending `[{date, close}]` shape; null closes skipped; malformed/HTML/
  error payloads return None (never raise).
- AC-2: source chain becomes yahoo → stooq → FMP (yahoo primary because it
  is the one that currently works; stooq kept in case the wall drops; FMP
  keyed last). Chain order pinned by a transport-fixture test.
- AC-3: the Yahoo request sends a browser User-Agent and maps dotted
  symbols to Yahoo's dashed form (BRK.B → BRK-B).
- AC-4: `fetch_eod`'s pinned contract is unchanged: signature, cache
  freshness/shape, never-raises, empty-on-total-failure, one summary log
  line, no key/URL leakage in logs (T-008 lesson).
- AC-5: all existing frozen T-014 tests stay green unmodified.
