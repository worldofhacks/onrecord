## Context
T-011's `ranked_search(index, query, k=10, k1=1.5, b=0.75, analyzer=None)` already exposes k1/b everywhere; this ticket ships the sweep that DEFENDS the chosen values. New module `onrecord/eval/sweep.py`:

- `sweep(index, judgments_path, k1_values=None, b_values=None, k=10, index_dir=None) -> dict` — defaults: k1 ∈ {0.0, 0.25, …, 2.5} (11 values), b ∈ {0.0, 0.1, …, 1.0} (11 values) = 121 cells (proposed grid; spans the scope-pinned ranges [0,2.5]×[0,1]). Per cell: mean NDCG@10 across the judgment queries (reuse `onrecord.eval.metrics.ndcg_at_k`; judgments row schema/grouping identical to eval/run.py's `_load_judgments` — reimplement the ~10-line loader or import the private helper, implementer's choice). Retrieval per query per cell via `ranked_search(index, query, k=<judgment-safe depth ≥ 10>, k1=k1, b=b)`. k1=0 and b=0 are LEGAL grid points (T-011 fix round guarded the k1=0 boundary — locked-decision; the sweep is the reason that guard exists). `index_dir: str | Path | None = None` exists because `InvertedIndex` exposes no source path (plan-review I-1) — the CLI passes its `--index` arg through; library callers may pass `None`.
- Return shape (also the JSON artifact shape): `{"grid": [{"k1": f, "b": f, "ndcg10": f}, ...], "best": {"k1": f, "b": f, "ndcg10": f}, "n_queries": int, "k": 10, "corpus_version": str, "index_dir": str | null}`. `corpus_version` read tolerantly from `<index_dir>/manifest.json` inline (3-line json read; `index_dir=None` OR missing/corrupt manifest → `"unversioned"`) — deliberately NOT imported from T-018 so this ticket has zero same-wave dependencies (proposed).
- Ties for `best`: highest ndcg10, then smallest (k1, b) lexicographically (proposed — deterministic and boring beats clever).
- CLI main: `uv run python -m onrecord.eval.sweep --index artifacts/index --judgments evalsets/judgments.jsonl --out artifacts/sweeps/k1b_ndcg10.json [--plot]`. `--plot` renders a heatmap PNG next to the JSON via matplotlib (added as a DEV dependency only — proposed; plotting is NOT exercised by frozen tests: font/renderer nondeterminism).
- Performance guidance (not an AC): gather each query's per-term postings/df/doc-length stats ONCE and re-score across the 121 cells rather than re-running full `ranked_search` per cell — at ~255K v2 docs × 15 queries the naive loop is hours, the re-scoring loop is minutes. Correctness is what's frozen; if the implementer ships the naive loop it must still produce identical numbers on the fixtures.
- README: add a "Defended k1/b" section — grid summary table placeholder, the chosen (k1, b), and a 1-paragraph defense template; the orchestrator fills measured corpus-v2 numbers after the operational sweep run (the rubric line is the DEFENSE, so the section structure ships here even though the final numbers land at integration).
- **HARD PRECONDITION on the official numbers (orchestrator adjudication, plan-review C-4):** measured BM25 NDCG@10 on v2 with the v1-pooled judgments is 0.173 — pooling bias, not engine regression. The official sweep run and ANY "Defended k1/b" README number are sequenced AFTER the q1–q5 re-pool/re-judge against corpus-v2 (`evalsets/judgment-session-2.md`, "FIRST: top up q1–q5" section — already prepped, drift-guard-compatible resume). ## Acceptance Criteria
- **AC-1**: With defaults, the grid contains exactly 121 cells covering exactly the k1/b values above; every `ndcg10` is a finite float in [0, 1].
- **AC-2**: On a hand-built fixture index where the only grade-2 doc is 3× longer than a competing grade-0 doc with equal tf, the direction is explicit: `ndcg10(k1=1.5, b=0.0) > ndcg10(k1=1.5, b=1.0)` (b=0 scores the docs equally so the relevant doc is not length-penalized; b=1 demotes the long relevant doc below the short grade-0 doc — inequality written into the ticket per plan-review M-10).
- **AC-3**: On a fixture where the only grade-2 doc has tf=10 for the query term vs a grade-0 doc's tf=1 (equal lengths), the direction is explicit: `ndcg10(k1=2.5, b=0.75) > ndcg10(k1=0.0, b=0.75)` (k1=0 ignores tf entirely so the two docs tie; k1=2.5 rewards the higher-tf relevant doc). Both boundary cells run without error (k1=0 regression guard).
- **AC-4**: `best` selects the max-ndcg10 cell; on a constructed exact tie, the smallest-(k1,b) cell wins deterministically.
- **AC-5**: The CLI main writes the JSON artifact matching the return shape exactly (round-trips), including `n_queries` and `corpus_version` ("unversioned" when `index_dir=None` or no manifest; "v2" when a manifest fixture is present; `index_dir` echoes the CLI arg and is null when absent).
