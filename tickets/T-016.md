## Context
ui/OnRecord App.dc.html is the studio-delivered SPA (dc-runtime; ui/support.js). It renders 5 views from EMBEDDED SAMPLE DATA (CORPUS array, seeded-RNG series(), hardcoded METRICS/SECTORS/FEATURED). Task: swap the data layer to the live API while preserving the design's rendering, interactions, and graceful states EXACTLY. The API contracts are pinned in tests/unit/test_api.py's module docstring (search/tickers/metrics/answer) and tests/unit/ingest/test_prices.py's (prices payload).

Wiring map (verification: manual checklist, no pytest):
1. apiBase: default '' (same-origin — the API serves this UI); keep the prop override.
2. Search: replace currentResults()'s local scoring with debounced (250ms) GET /api/search?q=&k=20&op=OR + filter params (source/venue/ticker/jurisdiction from the filter pills); map results {doc_id→id, snippet→text segments (parse <mark> for highlights — replace segs()'s term-matching with mark-span parsing), source_type→source, venue_type→venue, deep_link→link, ts derived from &t=NNNs in the link (mm:ss), line composed as "<Jurisdiction · source label · date>"}. Keep keyboard nav + selIdx behavior. Empty query → keep showing latest (fetch with a default query or hide list — designer's empty state preferred).
3. Tickers view: GET /api/tickers once per visit → sectors/receipt counts replace SECTORS/FEATURED; keep NAMES as display fallback.
4. Detail pane series: GET /api/prices/{sym}?range=365 → real closes; significant_moves plotted as the receipt markers (mkI interactions intact); while loading or empty series, show the design's existing loading/empty treatment (add a subtle "price data unavailable" state if none exists — match the design language). Remove the fake shock injection.
5. Scoreboard: GET /api/metrics → rows; empty → an honest "no eval runs yet — red harness pending labels" state in the design's voice. Remove hardcoded METRICS.
6. Ask: verify the existing POST /api/answer handler sends {question, mode, k} and renders the available_thursday teaser gracefully; fix the request shape if it drifts from the pinned contract.
7. The sample CORPUS array may remain ONLY as the documented api-down demo fallback if the design already has an apiDown state that uses it — label it "demo data" visibly in that state; never show it when the API is live.
8. index.html: create ui/index.html as the servable copy (exact copy of the wired OnRecord App.dc.html; keep the original filename too for design round-trips).
