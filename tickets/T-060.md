## Context

We index 8-K bodies but never classify them. 8-K items are a fixed
taxonomy (Item 1.01 material agreements, 2.03 debt obligations, 5.02
officer changes, 7.01 Reg FD, 8.01 other events, ...). Item headers are
formulaic text -> deterministic extraction, no LLM.

## Build sketch

- `onrecord/analysis/events8k.py`: scan indexed edgar 8-K docs for item
  headers (pattern grammar pinned: "Item 1.01", "ITEM 2.03.", spacing/
  punctuation variants from the real corpus); emit {doc_id, ticker,
  filing_date, items:[codes], deep_link}. Taxonomy table maps code ->
  human label (frozen, complete for the 9xx/1-8 families).
- Feed: /api/events?ticker=...&window=... ordered by date; joins mentions
  chart as event markers (diamond convention from T-049 insiders — new
  marker glyph, distinct legend).
- Aggregate: per-ticker event-type counts for the Conduct strip
  ("3 material agreements, 2 debt events this quarter").
- UI: Tickers detail gains MATERIAL EVENTS list with receipts; chart
  markers hover shows item labels. Both UI files byte-identical.

## Acceptance criteria

- AC-1: extraction grammar pinned by fixtures drawn from real corpus 8-Ks incl. formatting variants; false-positive corpus (item references in prose like "pursuant to Item 1.01 of a prior filing" in 10-Ks are NOT events — scope to 8-K docs only).
- AC-2: every event row's doc exists and is an 8-K section doc; deep links resolve to existing receipt format.
- AC-3: taxonomy covers all items observed in the corpus (build fails listing unknown codes rather than dropping them silently).
- AC-4: API keyless; chart markers additive and distinct from insider diamonds.
- AC-5: both UI files byte-identical.

## Out of scope

LLM summarization of events (v2), non-8-K event inference, materiality scoring.
