## Context
Owner-approved scope addition: stock price history + significant-move timeline joined to receipts. onrecord/ingest/prices.py:
- `fetch_eod(ticker, range_days=365, transport=None) -> list[{date, close}]` — stooq CSV endpoint (no key: q=<ticker>.us) primary, FMP `historical-price-full` fallback when FMP_API_KEY set; on-disk cache (artifacts/prices/<ticker>.json, content-dated, re-fetch only if stale >1 day). Failures → [] + log (never raise).
- `significant_moves(series, threshold_pct=5.0) -> list[{date, return_pct}]` — daily |close-to-close return| ≥ threshold.
- `nearby_receipts(moves, corpus_rows, ticker, window_days=7) -> moves + receipts` — docs matching ticker (or jurisdiction-mapped for county docs — SKIP jurisdiction mapping v1, ticker only) dated within window_days BEFORE each move date.
- `api_payload(ticker, corpus_path, ...) -> {"ticker", "series", "significant_moves":[{date, return_pct, nearby_receipts:[...]}]}` — the exact /api/prices contract (T-013's api.py wires the route later; to avoid file-scope collision, this ticket exposes the function only — the route lands in the wave-5 integration commit by the orchestrator).

## Acceptance Criteria
- **AC-1**: Given a fixture CSV (stooq shape), fetch_eod parses ordered {date, close} rows; malformed rows skipped+logged.
- **AC-2**: Given a series with a -8.2% day and a +5.1% day and threshold 5.0, exactly those two dates return with correct signed return_pct.
- **AC-3**: Given corpus rows for the ticker dated 2 and 9 days before a move (window 7), only the 2-day-prior doc attaches as nearby_receipt.
- **AC-4**: Given cache present and fresh, fetch_eod performs zero network calls (mocked transport asserts no requests).
- **AC-5**: Given both sources failing (mocked), fetch_eod returns [] with one log line — no exception.
