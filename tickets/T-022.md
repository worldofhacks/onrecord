## Context
Pure retrieval functions consumed by T-024's API wiring; no FastAPI here. Consumes T-020's `Chunk`/`chunk_corpus` and T-021's `EmbeddingStore`/`get_provider`/`cosine_top_k`. The shipped chunking is IDENTITY (chunk_id == doc_id, T-020 locked invariant), so every `SearchResult.doc_id` returned here remains a valid corpus doc id resolvable via `index.get_doc` — REQUIRED for the frozen 9-key /api/search result shape (locked-decision). RRF k=60 is a standing decision (locked). All frozen tests run keyless with FakeProvider + tiny fixture stores.

`onrecord/rag/retrieve.py`:
- `semantic_search(store, chunks, query, provider, k=10) -> list[SearchResult]` — embed the query via `provider`, `cosine_top_k` over `store`, then map rows to chunks **CHUNK_ID-KEYED, never positionally** (orchestrator adjudication of plan-review C-3, revised by the T-021 C-1 id-space ruling 2026-08-12: entries are per-chunk, `entries.json` maps `chunk_id -> {row, content_hash}`; dedupe is API-call-level inside T-021 and invisible here): resolve rows via `store.rows_for(chunk_ids)` — NOTE the argument is chunk_ids, NOT content hashes; both are `str`, so passing hashes fails SILENTLY as a total miss (a frozen tripwire test in T-021's suite guards this) — build the row→chunk mapping from that, and VERIFY correspondence — the store entry's recorded `content_hash` must equal `content_hash(model, dim, chunk.text)` (T-021's frozen public helper — import it, never re-derive the formula) for every resolved row (stale text → mismatch) (mismatch → typed `StoreMismatch` error naming both ids). Chunks with no store row → typed `MissingEmbeddings` naming the count (never silently skipped — a wrong receipt is the product's worst failure). Store rows not covered by `chunks` (prior embed runs, other corpus versions) are simply never surfaced. `SearchResult(doc_id=chunk.chunk_id, score=<cosine float>, snippet=chunk.text[:160])` (SNIPPET_LEN=160 convention, T-014R precedent).
- `rrf_fuse(rankings: list[list[str]], k: int = 60) -> list[tuple[str, float]]` — score(id) = Σ over rankings containing id of 1/(k + rank), rank 1-based; sort score desc, ties by id asc (deterministic). Ids absent from a ranking simply contribute nothing (no penalty term).
- `hybrid_search(index, store, chunks, query, provider, k=10, rrf_k=60) -> list[SearchResult]` — **fusion is defined over ONE id space: chunk_id** (orchestrator adjudication of plan-review I-11). The lexical ranking comes from `ranked_search(index, query, k=index.doc_count())` (full depth: RRF needs deep rankings, and ranked_search scores its full candidate set regardless of k — same rationale as api.py's op=AND path), whose ids are CORPUS DOC ids — valid fusion input ONLY under the identity invariant (chunk_id == doc_id). `hybrid_search` therefore GUARDS: every chunk must satisfy `chunk.chunk_id == chunk.doc_ids[0] and len(chunk.doc_ids) == 1`, else raise typed `NonIdentityChunking` — fail loud, never degenerate into a no-overlap concatenation (adopting window>1 needs a chunk-level lexical index; deferred, see T-020 Out of Scope). Semantic ranking = `semantic_search(..., k=len(chunks))` id sequence; fuse; top-k as SearchResults with `score=<RRF score>`, snippet from the lexical hit when the id appeared lexically (positions-based snippets are strictly better) else `chunk.text[:160]`. The chunk_id→doc_id projection at the API boundary is T-024's explicit responsibility.

`onrecord/rag/modes.py` — the side-by-side report (spec §5 requires all three modes on the same queries):
- `report_modes(index, store, chunks, judgments_path, provider, history_path="artifacts/modes_scoreboard.jsonl") -> list[dict]` — for mode ∈ (lexical, semantic, hybrid): retrieve per judgment query, score the SAME six-label metric set as eval/run.py (`P@5, P@10, R@10, R@50, MRR, NDCG@10` via onrecord.eval.metrics), append one row per mode: `{"timestamp", "git_sha", "corpus_version", "mode", "metrics": {"per_query", "mean"}}`. Writes its OWN artifact — eval/run.py's history-row key set is frozen by test_metrics.py and MUST NOT gain a mode field (locked constraint); a separate mode-tagged scoreboard sidesteps the frozen contract. `corpus_version` via `read_manifest` from T-018 (merged by wave 9).
- CLI main mirroring eval.run's pattern (index dir, judgments, store dir args).

## Acceptance Criteria
- **AC-1**: `rrf_fuse` hand-computed — two rankings sharing some ids: exact scores (e.g. id in ranks 1 and 3 → 1/61 + 1/63), ids present in only one ranking scored correctly, ordering + id-asc tie-break deterministic.
- **AC-2**: `semantic_search` on a 5-chunk fixture store (FakeProvider, hand-set vectors) returns SearchResults in hand-computed cosine order with `doc_id == chunk_id`, float scores, 160-char-max snippets. **Permuted-store proof (plan-review C-3 — this AC fails a positional design):** a store whose rows were written in a DIFFERENT order than `chunks`, and which contains extra rows from a prior embed run, still returns the correct chunk for every row; a store entry whose recorded chunk_id disagrees with the chunk raises `StoreMismatch`; a chunk absent from the store raises `MissingEmbeddings` naming the count.
- **AC-3**: `hybrid_search` on a fixture where lexical and semantic disagree: fused order matches hand-computed RRF; a doc found ONLY semantically still surfaces (with chunk-text snippet); a doc found ONLY lexically still surfaces (with its lexical positional snippet); k-truncation exact.
- **AC-4**: Identity guard + round-trip — with identity chunking, every returned doc_id resolves via `index.get_doc` (locked-invariant guard); with a merged chunk (`window=2` fixture, chunk_id `...+w2`) in the input, `hybrid_search` raises `NonIdentityChunking` instead of returning a degenerate fusion (plan-review I-11).
- **AC-5**: `report_modes` with FakeProvider + fixture judgments appends EXACTLY three rows (one per mode) with the pinned row key set and six-label metrics; per-mode numbers match hand computation on the fixture; eval/run.py's artifacts are untouched.
