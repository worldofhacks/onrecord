## Context
The answer pipeline as a pure library — T-024 wires it to POST /api/answer. The JSON shape is the PINNED-FOR-THURSDAY contract frozen in tests/unit/test_api.py's docstring (`answer_id, text, citations[{n, doc_id, deep_link, snippet}], retrieved[9-key + cited], grounding{status, supported_claims, total_claims}, refusal: null | {reason, suggestions}`) — locked; never renegotiate, the UI Ask view is being wired to it by T-028. Generation is non-deterministic ⇒ per the swarm rule, `generate_fn: Callable[[str], str]` is INJECTED; every AC below is frozen against fakes. Claim segmentation comes from `onrecord.rag.claims.split_claims` (T-027, merged in wave 8 — the single segmentation authority shared with T-026's judge so grounding counts and judged claims segment identically [locked consistency decision]; claims.py was split out of this ticket per the adversarial-review sizing verdict).

`onrecord/rag/answer.py`:
- `build_prompt(question, chunks: list[Chunk]) -> str` — numbered context blocks `[1]..[m]` **in chunk order, 1-based** (the citation parser's validity range depends on exactly this numbering — plan-review I-7), each block carrying its chunk's `deep_link` and date/venue metadata; instructions: answer ONLY from the context; append `[n]` markers to each supported sentence; output the literal sentinel `INSUFFICIENT_CONTEXT` if the context cannot answer. Chunk texts are included verbatim — prompt size is bounded by construction (k ≤ 10 chunks × ~75s caption windows / EDGAR sections).
- **Generator model — single source of truth (plan-review I-8):** `default_generator()` reads `ONRECORD_GENERATOR_MODEL` (falling back to a module constant `DEFAULT_GENERATOR_MODEL` — value set by the implementer from verified-current Claude-family model ids [research-required: verify live, never from memory]); expose `resolved_generator_model() -> str` returning the id actually in use. T-026's cross-family gate consumes THIS value (as an explicit parameter wired at eval time) — no second env lookup anywhere. Claude-family per the cross-family standing decision [locked]; keyless (`ANTHROPIC_API_KEY` absent) → typed `GeneratorNotConfigured` (key provisioning = owner open question #2).
- `answer(question, chunks, generate_fn, *, min_confidence: float | None = None, retrieval_scores: list[float] | None = None) -> dict` returning EXACTLY the pinned shape (no `mode` parameter — it surfaced in no output key; callers who need the mode label carry it themselves — plan-review M-5):
  - **Retrieval-confidence refusal (deterministic, decided BEFORE generation):** if `chunks` is empty, or `min_confidence` is set and `max(retrieval_scores) < min_confidence` → return with `refusal = {"reason": <names the confidence gap>, "suggestions": [<2-3 reformulation hints derived from the question terms>]}`, `text` = one short decline sentence (proposed: the UI needs something renderable), `citations=[]`, all `retrieved[].cited=False`, `grounding={"status":"ungrounded","supported_claims":0,"total_claims":0}`, and `generate_fn` is NEVER called. The threshold VALUE is tuned later on T-025's sets (research-required); the MECHANISM is frozen here.
  - **Generation-side refusal:** generated text containing `INSUFFICIENT_CONTEXT` → same refusal shape (reason: model judged context insufficient).
  - **Citation post-processing (deterministic):** parse `[n]` markers from the generated text. Valid n ∈ [1, len(chunks)]. DANGLING markers (out-of-range n) are stripped from `text` and excluded; an UNTERMINATED marker (`[1` with no closing bracket, e.g. a max_tokens cutoff — plan-review M-6) is NOT a marker: it stays literal text and supports nothing. `citations[]` = one entry per DISTINCT valid n in first-appearance order, `{n, doc_id: chunk.chunk_id, deep_link: chunk.deep_link, snippet: chunk.text[:160]}` (every citation is a deep link — spec §5). `retrieved[]` = the SAME 9-key dict shape as /api/search results (doc_id/score/snippet/date/source_type/venue_type/jurisdiction/ticker/deep_link — locked) built from the input chunks, plus `"cited": bool` true iff that chunk's id appears in citations. `retrieved[].score` = the matching `retrieval_scores` value; **when `retrieval_scores` is None, score is pinned `0.0`** (plan-review M-4 — never an invented value); a non-None `retrieval_scores` whose length mismatches `chunks` raises ValueError.
  - **Claim-level grounding (deterministic):** claims = `split_claims(text)` after dangling-marker stripping; a claim is SUPPORTED iff it contains ≥1 valid marker. `grounding = {"status": "grounded" if supported==total and total>0 else "partial" if supported>0 else "ungrounded", "supported_claims": int, "total_claims": int}`.
  - `answer_id` = `uuid.uuid4().hex` (pinned as: non-empty str, unique across two calls).
- Whether a chunk's citation entry is FAITHFUL (the chunk actually entails the claim) is T-026's LLM-judge territory — grounding here is the deterministic marker-coverage layer only (locked split).

**AMENDMENT (2026-08-12, T-027 adjudication):** the generation prompt MUST instruct prose-only answers — no numbered/bulleted lists — because claim segmentation deliberately does NOT merge enumerators (a merge rule was proven structurally incompatible with the count-invariant property; enumerated answers shatter into junk claims that ground pessimistically). Pin the instruction's presence in the prompt-assembly test.

## Acceptance Criteria
- **AC-1**: Happy path with a FakeGenerator emitting two cited sentences over 3 chunks: response has EXACTLY the pinned top-level key set; citations exactly the distinct valid ns in first-appearance order with correct doc_id/deep_link/snippet; cited flags correct; grounding == grounded (2/2); refusal is None (JSON null); with `retrieval_scores=None` every `retrieved[].score == 0.0`, with scores given they map through 1:1, and a length mismatch raises ValueError.
- **AC-2**: Malformed markers — FakeGenerator emits a dangling `[7]` over 3 chunks: stripped from `text`, absent from citations, its claim counts unsupported; separately an unterminated `[2` (cutoff simulation) stays literal in `text`, creates no citation, and its claim counts unsupported.
- **AC-3**: Mixed support — 3 claims, 2 carrying valid markers → `{"status": "partial", "supported_claims": 2, "total_claims": 3}` exactly.
- **AC-4**: Retrieval-confidence refusal — empty chunks, and separately max score below min_confidence: refusal object populated (reason str, ≥1 suggestion), generate_fn NOT called (call-count assert), grounding ungrounded 0/0, text non-empty decline.
- **AC-5**: Generation-side refusal — FakeGenerator returns `INSUFFICIENT_CONTEXT` → refusal object, no citations.
- **AC-6**: `build_prompt` structure (asserted on OUR string, not LLM behavior — plan-review I-7): over 3 chunks the prompt contains exactly the markers `[1]`, `[2]`, `[3]` in chunk order, each block contains its chunk's `deep_link`, and the literal `INSUFFICIENT_CONTEXT` sentinel appears in the instructions.
- **AC-7**: Config surface — `answer_id` non-empty and distinct across two calls; with `monkeypatch.delenv("ANTHROPIC_API_KEY", raising=False)` `default_generator()` raises `GeneratorNotConfigured` naming the env var, and with the var set to a sentinel it constructs without raising (both branches pinned — plan-review I-5); `resolved_generator_model()` returns the `ONRECORD_GENERATOR_MODEL` override when set, else `DEFAULT_GENERATOR_MODEL`; the API key never appears in any root-logger record during a mocked generation call (LESSONS T-014 sentinel).
