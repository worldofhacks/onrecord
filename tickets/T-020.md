## Context
Corpus docs ARE the retrieval units (75s caption windows for yt; section-level for EDGAR) and the 49 judged yt doc_ids (`yt:VIDEO:segNNN`) survive the v2 re-parse verbatim — so chunking for the RAG path produces ALTERNATE groupings that REFERENCE corpus doc ids and must NEVER rewrite, reshape, or re-mint them (locked-decision: the judgment set depends on doc-id stability). First files in the new `onrecord/rag/` package; `onrecord/rag/__init__.py` and `tests/unit/rag/__init__.py` are EMPTY shared files also created by T-021 in this wave — the empty-`__init__` auto-merge precedent from wave 2 (T-006/7/8) applies; put nothing in them.

`onrecord/rag/chunking.py`:
- `@dataclass(frozen=True) Chunk`: `chunk_id: str`, `doc_ids: list[str]` (constituent corpus doc ids, verbatim, in order), `text: str`, plus metadata passthrough from the FIRST constituent doc: `deep_link, date, source_type, venue_type, ticker, jurisdiction, speaker` (contiguous windows of one video share metadata; the first window's deep_link timestamps the chunk start).
- `chunk_corpus(docs: list[Doc], window: int = 1, overlap: int = 0) -> list[Chunk]`. Validation: `window >= 1`, `0 <= overlap < window` else ValueError. Docs whose id matches `yt:<video>:seg<NNN>` group per video, ordered by NNN, and merge into sliding windows of `window` segments with stride `window - overlap` (a final short window keeps the tail; windows never cross videos). ALL other docs (EDGAR sections etc.) pass through as identity chunks unconditionally — they are already section-level (locked-decision, spec §2.3). Chunk ids: identity chunk → `chunk_id == doc_id` EXACTLY (locked-decision — this invariant is what lets the shipped API path keep returning valid corpus doc ids, see T-022/T-024); merged chunk → `f"{doc_ids[0]}+w{window}"` (unique: first segment differs per window). Text join: single space.
- `window=1, overlap=0` is the identity chunking for the ENTIRE corpus (every chunk_id == doc_id) — the shipped default until the sweep defends otherwise.

`onrecord/rag/chunk_sweep.py`:
- `chunk_sweep(docs, judgments_path, windows=(1,2,3,4), overlaps=(0,1), k_values=(5,10), retrieve_fn_factory=None, min_grade=1, manifest_dir=None) -> dict` — per VALID cell (overlap < window; 7 cells at defaults — proposed grid: 75/150/225/300s windows, 0 or 1 segment overlap): build chunks, then recall@k of RELEVANT chunks per judgment query, mean over queries. **Relevance concept: "coverage relevance"** — a chunk is coverage-relevant iff any of its `doc_ids` carries grade ≥ `min_grade` (default 1) in the judgment set. This is deliberately a DIFFERENT concept from T-025's "answer-grade derivation" (grade == 2 → QA answer docs) — the two thresholds serve different measurements and are named distinctly on purpose; BOTH are injected parameters so the owner's answer to open-question #6 is a config change, never a re-freeze (plan-review I-6). Default retrieval: in-memory `InvertedIndex.build([Doc(id=chunk.chunk_id, text=chunk.text, ...metadata...) for chunk in chunks])` + `ranked_search` (BM25) — deterministic, key-free. `retrieve_fn_factory(chunks) -> retrieve_fn(query) -> list[chunk_id]` seam lets T-022+ re-run the same sweep semantically later. `manifest_dir: str | Path | None = None` — the signature has no index dir of its own (plan-review I-1), so the manifest location is an explicit parameter; the CLI passes it. NEVER writes to `artifacts/index` (in-memory only — the real index stays corpus-doc-keyed).
- Return/artifact shape: `{"cells": [{"window": w, "overlap": o, "recall@5": f, "recall@10": f}], "best": {...by recall@10, ties → smallest (window, overlap)}, "n_queries": int, "min_grade": int, "corpus_version": str (tolerant inline read of <manifest_dir>/manifest.json; None/missing/corrupt → "unversioned"), "retrieval": "bm25"}`. CLI main writes `artifacts/sweeps/chunking_recall.json` (+ optional `--plot` PNG, dev-dep matplotlib, not frozen-tested — same convention as T-019).
- **Adoption honesty (plan-review I-11):** the shipped API/hybrid path runs IDENTITY chunking only. Adopting a swept `window > 1` requires a chunk-level lexical index for hybrid fusion (T-022 guards against non-identity input rather than fusing garbage) — that adoption path is deferred [scope-cut, recorded in Out of Scope and the README curve caption]. The curve is still the graded deliverable ("publish the curve", spec §5); this note is what makes it honest rather than decorative.

## Acceptance Criteria
- **AC-1**: Identity invariants — `window=1, overlap=0` over a mixed yt+EDGAR fixture yields one chunk per doc with `chunk_id == doc_id`, `doc_ids == [doc_id]`, text and all 7 metadata fields equal to the source doc's.
- **AC-2**: Grouping — `window=3, overlap=1` over videos A (seg000..seg004) and B (seg000..seg001) yields windows [A:0-2], [A:2-4], [B:0-1] (stride 2, tail kept, never cross-video); texts are the space-joined constituent texts in segment order; merged chunk_id is `f"{first_doc_id}+w3"`.
- **AC-3**: Non-yt docs are identity chunks at EVERY (window, overlap) setting.
- **AC-4**: Input doc ids are echoed verbatim in `doc_ids` — property test (hypothesis) over generated yt-shaped ids: the multiset of all constituent doc_ids equals the input id multiset with overlap=0, and no Chunk ever contains a string not present in the input ids.
- **AC-5**: Coverage-relevance mapping + recall math — on a fixture with grades {2, 1, 0}: at `min_grade=1` both the grade-2 and grade-1 docs' chunks are coverage-relevant, at `min_grade=2` only the grade-2 doc's chunk is (both thresholds pinned so OQ-6 resolves by config — plan-review I-6); a merged chunk covering one relevant doc counts as exactly one relevant chunk; recall@k values match hand computation; invalid cells (overlap ≥ window) are excluded from the grid.
- **AC-6**: Artifact shape round-trips exactly, including `best` tie-break determinism, the `min_grade` echo, and `corpus_version` behavior (`manifest_dir=None` → "unversioned"; a manifest fixture → its version).
- **AC-7**: `window=0`, `overlap=-1`, `overlap>=window` each raise ValueError with a message naming the parameter.
