## Context
The UI (in flight from a design studio) is built against these exact contracts. New file onrecord/api.py (FastAPI app; fastapi+uvicorn get added to pyproject deps — allowed here as the ticket's declared dependency change). Endpoints:
- `GET /api/search?q&mode=lexical&op=OR&k=20&source&venue&ticker&jurisdiction` → `{query, mode, results: [SearchResult-shaped dicts incl. metadata]}`. mode=lexical uses ranked_search when T-011 is merged, else falls back to boolean OR with score 0.0 (feature-detect via import — degrade gracefully). mode=semantic|hybrid → 200 with `{"error":"available_wednesday"}`.
- `GET /api/tickers` → registry sectors + per-ticker receipt_count (index df-based count of docs with that ticker) + last_receipt.
- `GET /api/metrics` → parsed artifacts/scoreboard.jsonl history (empty list when missing).
- CORS: allow localhost:5173. App startup loads index from artifacts/index (configurable via ONRECORD_INDEX env); missing index → 503 with clear message on data endpoints, /health always 200.

## Acceptance Criteria
- **AC-1**: Given a tmp index, /api/search returns results with all SearchResult fields + metadata (date, source_type, venue_type, jurisdiction, ticker, deep_link), filtered correctly by source/venue/ticker params.
- **AC-2**: mode=semantic returns 200 {"error":"available_wednesday"}; unknown mode → 422.
- **AC-3**: /api/tickers groups by sector with correct receipt counts on a tmp corpus.
- **AC-4**: /api/metrics returns [] when no scoreboard exists; returns parsed rows when it does.
- **AC-5**: Missing index dir → /health 200, /api/search 503 with actionable message.
