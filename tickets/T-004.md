## Context
Implements frozen `boolean_search(index, query, op)` + `phrase_search(index, phrase)` from T-001. Query terms go through `analyze()` — same function as indexing (the invariant). AND = k-way sorted intersection of posting doc_ids; OR = k-way union. Results as `SearchResult` (score 0.0 tonight — BM25 is Wednesday; snippet = first 160 chars of doc text containing a query term, naive is fine). Phrase: docs where terms occur at consecutive positions. May build tests with real T-002/T-003 implementations via the frozen interfaces (integration-style unit tests are fine; use tiny in-memory corpora).

## Acceptance Criteria
- **AC-1**: Given docs A("loudoun substation approved"), B("substation denied"), C("loudoun park"), when `boolean_search(idx, "loudoun substation", "AND")`, then exactly A returns.
- **AC-2**: Same corpus, op OR → A, B, C all return (any term matches).
- **AC-3**: Given query terms absent from corpus, when searched with AND or OR, then `[]` — no exception.
- **AC-4**: Given `phrase_search(idx, "data center")`, then only docs with "data" immediately before "center" return; a doc containing "data … center" apart does not.
- **AC-5**: Given an empty or punctuation-only query, when searched, then `[]` — no exception (robustness, Spec §4.5).
- **AC-6**: Given mixed-case query ("LOUDOUN Substation"), then results identical to lowercase (analyzer invariant).
