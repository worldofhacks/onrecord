## Context
Implements frozen metric signatures from T-001 plus the runner (`python -m onrecord.eval.run`, already wired to `make eval` by T-001). Runner: load `evalsets/judgments.jsonl` (rows: `{query_id, query, criterion, doc_id, grade}` grade∈{0,1,2}), run each query through boolean OR retrieval (frozen interface; ranked order = doc_id order tonight — scores arrive Wed), print a scoreboard table (P@5, P@10, R@10, R@50, MRR, NDCG@10 per query + means), append `{timestamp, git_sha, corpus_version, metrics}` to `artifacts/scoreboard.jsonl`. Exit code 1 if mean NDCG@10 < 0.5 — **red tonight by design**. Missing judgments file → clear error message, exit 2.

Metric definitions (binary relevance = grade≥1 for P/R/MRR; graded for NDCG; DCG = Σ rel_i/log2(i+1); NDCG = DCG/IDCG, 0 when IDCG=0).

## Acceptance Criteria
- **AC-1**: Given ranked `[a,b,c,d]` with relevant `{a:1, c:2, x:1}`, when P@2/R@2 computed, then P@2=0.5, R@2=1/3.
- **AC-2**: Given first relevant doc at rank 3, when MRR for that query computed, then 1/3; no relevant in ranking → 0.
- **AC-3**: Given ranked `[c,a]` with grades `{a:1,c:2}` and k=2, when NDCG@2 computed, then DCG=2/log2(2)+1/log2(3), IDCG=same ideal ordering → NDCG=1.0; reversed order < 1.0.
- **AC-4**: Given k larger than result list, when any metric computed, then no exception; math treats missing ranks as non-relevant.
- **AC-5**: Given a judgments file and a built index, when `python -m onrecord.eval.run` executes, then scoreboard prints all metrics per query + means, appends history JSONL, and exits 1 while NDCG mean is below threshold (red).
