Contracts:
- `class EmbeddingProvider(Protocol)`: attributes `model: str`, `dim: int`; `embed(texts: list[str]) -> np.ndarray` (float32, shape `(len(texts), dim)`, row order == input order).
- `OpenAIEmbeddingProvider(model="text-embedding-3-small", api_key=None, transport=None)` — POST `/v1/embeddings` via httpx, input batching (≤ 512 texts/request, proposed), retry with backoff on 429/5xx (max 3), bearer auth from `OPENAI_API_KEY` when `api_key` is None. Registry dict `PROVIDERS = {"openai": ...}` so a Voyage adapter is a one-entry follow-up once the owner decides (proposed shape, contingent on the open question — do NOT implement a Voyage adapter speculatively).
- `get_provider(name=None) -> EmbeddingProvider` — name from arg else `ONRECORD_EMBED_PROVIDER` env (default `"openai"`), model override via `ONRECORD_EMBED_MODEL`. Missing key → raise `ProviderNotConfigured` with an actionable message (which env var to set); NEVER silently return a fake (locked-decision: fakes are test-injected only).
- `EmbeddingStore` — the content-hash cache + matrix. Key: `sha256(f"{model}\n{dim}\n{text}")` hexdigest (`dim` is IN the key — models with a dimensions parameter must not poison the cache across dim changes at the same model name; plan-review M-9). On-disk layout under `artifacts/embeddings/<model>/`: `matrix.npy` (N×dim, **fp16, L2-normalized rows** — normalize once at ingest, locked to make cosine a dot product) + `entries.json` (hash → `{"row": int, "chunk_id": str}`). **Alignment is ID-KEYED, never positional** (orchestrator adjudication of plan-review C-3, same defect class as the LESSONS T-003/T-004 id-space collision): row order in the matrix is first-appearance order across ALL embed runs ever made against the store, so consumers MUST resolve rows via hashes and verify the recorded `chunk_id` — length equality proves nothing (any permutation passes it). API: `load(dir) / save(dir)`, `matrix` property, `rows_for(hashes) -> list[int|None]`, `entry_for(hash) -> {"row", "chunk_id"} | None`, and `embed_corpus(pairs: list[tuple[str, str]], provider, checkpoint_dir=None, checkpoint_every=4096) -> None` where each pair is `(chunk_id, text)` — embeds ONLY pairs whose hash is absent and appends, recording `chunk_id` per row (re-freezes are incremental across corpus versions — spec's cache requirement). Packed matrix, NOT per-vector files (265K tiny files would be pathological).
- **Integrity contract (plan-review I-10 — this store fronts a multi-hour, ~$30-80, 265K-item run against a flaky hosted API):** (a) `save` is ATOMIC — write both files to temp names in the target dir, then `os.replace`; an exception mid-save leaves any previously-saved store loadable. (b) `embed_corpus` CHECKPOINTS — when `checkpoint_dir` is set, it saves after every `checkpoint_every` newly-embedded items, so a crash/provider-exhaustion resumes from cache instead of forcing a paid re-embed. (c) `load` VALIDATES — `len(entries) == matrix.shape[0]`, row indices are exactly `0..N-1` with no duplicates, dtype fp16 — any violation raises a typed `CorruptStore` naming the file and the mismatch (never a silent mis-map).
- `cosine_top_k(store, query_vec_f32, k, block_rows=8192) -> list[tuple[int, float]]` — blocked fp16→fp32 dot product (normalize the query too), deterministic ties by row index ascending.
- **Memory/latency estimate (required by scope, measured-at-runtime numbers to be recorded by the orchestrator):** ~265K chunks at identity chunking. 1536-d (text-embedding-3-small): 265,000 × 1536 × 2 B ≈ **0.78 GB fp16** resident (+ ≤ 8192×1536×4 B ≈ 50 MB fp32 per block during scoring — blocking keeps the transient bounded). 1024-d (Voyage class): ≈ 0.52 GB. Brute-force query ≈ 0.8 GFLOP → est. 50–150 ms/query in numpy on this machine. Under the spec's ~300K brute-force threshold ⇒ **hnswlib: scope-cut** (documented, with the recall-vs-exact check therefore moot at this scale).

## Acceptance Criteria
- **AC-1**: Cache hit — `embed_corpus` twice with identical (chunk_id, text) pairs: second call makes ZERO provider calls (counting FakeProvider) and the matrix is unchanged.
- **AC-2**: Incremental — 3 cached + 2 novel pairs: provider receives EXACTLY the 2 novel texts; `rows_for` maps all 5 hashes to correct rows; each entry records the correct `chunk_id`; row vectors round-trip (fp16 tolerance) to the fake's outputs, L2-normalized. Cache keys differ across `dim` at the same model name (M-9 guard: same text, dim 8 vs dim 4 FakeProviders → distinct entries, no collision).
- **AC-3**: Store round-trip + atomic save — save/load preserves dtype fp16, shape, and the full entries mapping exactly; loading a missing dir raises a clear FileNotFoundError-derived error; a save interrupted mid-write (monkeypatched np.save raising after the first file) leaves the previously-saved store fully loadable (temp+rename asserted by behavior, not implementation spying).
- **AC-4**: `cosine_top_k` — hand-computed similarities on 4 known vectors: correct order, correct scores (±1e-3 for fp16), deterministic tie-break, k-truncation, and blocked path (block_rows=2) equals unblocked results.
- **AC-5**: OpenAI adapter via httpx.MockTransport — request URL/model/auth header/batch split (513 texts → 2 requests) all asserted; a 429-then-200 sequence succeeds. Key-absence pinned robustly (plan-review I-5): with `monkeypatch.delenv("OPENAI_API_KEY", raising=False)` and no api_key arg → `ProviderNotConfigured` naming OPENAI_API_KEY; mirrored branch — with the var set to a sentinel value, construction succeeds without raising (both branches pinned, neither environmentally lucky).
- **AC-6**: Secret-leak sentinel — with a sentinel key value and a root-level capturing handler attached (ALL loggers, propagation on), a mocked embed call produces zero log records containing the sentinel.
- **AC-7**: `CorruptStore` validation — an entries/matrix row-count mismatch, a duplicate row index, and an out-of-range row index each raise `CorruptStore` at `load` with a message naming the defect; a valid store loads clean.
- **AC-8**: Checkpoint resume — FakeProvider raises on its 3rd batch mid-`embed_corpus` (checkpoint_every=2, checkpoint_dir set): reloading the checkpoint and re-running embeds ONLY the not-yet-embedded pairs (provider call count proves it) and the final store equals the never-crashed result.
