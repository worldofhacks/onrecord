## Context

1,527 promises are recorded but never checked. v1 is a deterministic
follow-up-trail engine in the Dodge-Index style: for each promise, scan the
SAME jurisdiction's LATER documents for matching evidence; every trail hop
carries a receipt. HONESTY PIN (copy-reviewed): the record can show a
promise was followed up or has gone quiet — it can NEVER assert "broken" or
"kept" (we observe mentions, not ground truth). UI language: "followed up
in the record (N receipts)" / "no further mention in the record since
YYYY-MM-DD". This phrasing is part of the frozen API contract.

## Build sketch

- `onrecord/analysis/outcomes.py`: per promise -> candidate follow-ups =
  docs where (jurisdiction matches) AND (doc.date > promise doc date) AND
  (match signal fires). Match signals, deterministic, in priority order:
  (a) quantity echo — a T-056 quantity of the same kind within a tolerance
  band (pinned: exact value, or same value in different unit form);
  (b) entity echo — registry ticker/company alias from the promise quote
  (word-boundary rules from T-033 mentions);
  (c) phrase echo — distinctive n-gram (>=4 content tokens) of the quote.
  Each trail row: {promise_id, doc_id, date, signal, matched_span,
  deep_link} — matched_span verbatim substring of the follow-up doc.
- Status derivation (pinned enum): followed_up (>=1 trail row),
  quiet (0 rows AND newest same-jurisdiction doc is >90 days after the
  promise), too_recent (0 rows, <90 days of later record). No other states.
- Artifact: artifacts/promise_outcomes.json + build lane in Makefile
  refresh. Full-corpus scan budget: <60s (Dodge scans 2.5s; this is
  per-promise x filtered-docs — index by jurisdiction first).
- API: /api/promises rows gain optional `outcome` {status, trail:[...k<=5]};
  /api/outcomes/summary {followed_up, quiet, too_recent, by_jurisdiction}.
- UI: Ledger cards get status tag + expandable trail with receipts;
  jurisdiction rollup "X promises, Y followed up, Z gone quiet".

## Acceptance criteria

- AC-1: every matched_span is verbatim in its follow-up doc; every trail doc is strictly later and same-jurisdiction (frozen tests).
- AC-2: status enum is exactly {followed_up, quiet, too_recent} with the 90-day boundary pinned; no "broken/kept" strings anywhere in code or UI (grep-gated test).
- AC-3: quantity-echo tolerance rules pinned by table-driven tests (incl. unit-form crossings from T-056).
- AC-4: full-corpus build completes <60s on the dev corpus snapshot (perf smoke).
- AC-5: /api/promises backward-compatible; trail rows carry working deep links (existing receipt formats only).
- AC-6: both UI files byte-identical.

## Out of scope

Verdicts on promise fulfillment, cross-jurisdiction trails, external (non-corpus) evidence — that arrives with T-059's queue join as a SEPARATE labeled signal, never merged silently.
