## Context

Datacenter developers appear in county hearings behind project shells
("Project Sail", "Sail Holdings LLC") while the real party appears in SEC
filings or later coverage. v1 is deliberately CURATED, not inferred: mining
proposes candidates, a human-auditable alias table asserts links, and every
link carries receipts from the corpus itself. Never present an inferred
link as fact — unlinked shells stay "unresolved" in the UI, which is
itself useful civic information.

## Build sketch

- Mining pass (`shells.py`): candidate shell names from county docs via
  deterministic patterns ("Project <Name>", "<Name> LLC/Holdings/Partners",
  case-preserved), frequency- and jurisdiction-scoped; emits
  artifacts/shell_candidates.json {name, jurisdictions, first_seen,
  n_docs, sample_receipts[3]}. Frozen tests pin the pattern grammar +
  false-positive corpus ("Project Manager", "LLC" alone, road names).
- Link evidence pass: for each candidate x registry company, co-occurrence
  receipts = docs (any source) where shell name and company/alias appear
  within the same doc; emits ranked evidence lists. NO auto-linking.
- Curated table: data/shell_links.json {shell, ticker|org, receipts:[doc_id...],
  confidence: "confirmed"|"reported", note} — committed, reviewed rows only
  (owner or explicit evidence: a filing naming the shell, or the company
  naming the project). Loader validates every receipt doc_id exists and
  actually contains the shell string (verbatim pin at load).
- API: /api/shells {resolved:[...], unresolved:[...]}; search results and
  promise/outcome rows for docs mentioning a resolved shell gain
  `appearing_as` metadata.
- UI: badge on receipts "appearing as Project Sail (NVDA — confirmed, 3 receipts)";
  unresolved shells listed on Ledger as "unidentified parties on the record".

## Acceptance criteria

- AC-1: loader rejects any curated row whose receipts don't verbatim-contain the shell name (frozen test with corrupt fixture).
- AC-2: mining false-positive corpus passes; candidates are reproducible from the corpus alone.
- AC-3: no auto-link path exists: absent a curated row, a shell can only render as unresolved (grep/behavior test).
- AC-4: API additive; UI files byte-identical.

## Out of scope

Probabilistic entity resolution, state corporate-registry scraping (research agent may open this as its own ticket), person-level identity.
